# PocketWorld Windows 混合桌面能力

Windows Companion 继续作为手机 Agent 的执行端：结构化观察与操作由
agent-desktop 承担，显式视觉操作由 Cua Driver 承担，手机上的人工观看由
WebRTC 视频承担。手机保留 Agent 推理、模型凭据、任务与授权；电脑上的三个
可执行文件共同受原 Companion 管理。

## 正式入口与使用流程

**从零首装（仅适用于确实取得的 Windows x64 正式签名发行）**：需要完整 Windows
程序包 ZIP，以及该包同版的 `Install-Companion.ps1`。另从可信发布方核对 ZIP 的
完整 SHA-256（64 个十六进制字符）与代码签名证书的 40 个十六进制指纹字符。
不要从待安装 ZIP 或旁边的 JSON 自行取这两个值当作信任来源。先在 Windows
文件属性的数字签名中核实脚本签名有效、签名者与独立资料一致，再用文件资源管理器
右键 **使用 PowerShell 运行** 这个脚本（无参数，使用标准用户的 Windows PowerShell）。
只选择保存在本机的原 ZIP；分步粘贴两项资料、查看核实的版本/提交/位置，明确确认才安装。
签名缺失、未知或系统策略阻止脚本时应停止，不需放宽策略或使用开发开关。源码归档、
Android APK 或开发 ZIP 不适用；这里说明的是产品入口，不表示已发布 Windows 安装包。

安装成功后可**只打开本机工作台**，或直接关闭。选打开才会复核刚装好的准确版本并进入
原生准备页；不会顺带配对、注册命令、启动服务或开启登录自启。以后在资源管理器
打开 `%LOCALAPPDATA%\PocketWorld\Companion`，右键 `Manage-Companion.ps1` 选择
**使用 PowerShell 运行** 即进入同一工作台（原脚本默认 `OpenDesk`）。已有安装、
中断恢复或开发包保持原维护方式，本图形首装不替换已有状态。

**电脑第一次使用：**在已解锁的 Windows 桌面打开当前安装目录的
`PocketWorld-Companion.exe`，即显示本机准备页；也可从固定的
`Manage-Companion.ps1 -Action OpenDesk` 打开同一页。打开或刷新不监听网络，
不改授权。全新签名安装可选 **登记这台电脑的设备身份**：确认后只登记本机私有身份和配置，不必选择工作文件夹，不会配对或启动服务。也可另选工作文件夹初始化。

1. 在电脑点 **打开本机配对与范围核对**。确认手机与电脑使用可互达的地址，创建一次性邀请。在手机 **我的设备 → 配对设备 → 对方已发邀请** 导入原邀请，双方分别核对完整指纹和这次的准确权限。
2. 电脑确认后保留原窗口，在手机 **我的设备 → 配对进展** 点这次的 **继续原配对**。Windows 显示已保存配对，只说明电脑端已完成本次配对提交；还须在手机 **配对伙伴** 中核对是否已出现这台电脑。列表编号可与电脑配对页所示的末六位对照，只用来找列表中的设备，不能代替完整证书指纹。手机还显示原配对未完成时，回看这次的原记录，不另造一条配对。
3. 即使手机能找到这台电脑，也不代表连接服务已启动、已经接通或获准使用桌面、文件。核对本机设置后可明确选择原配对窗的 **启动桥接（不重放旧任务）**，再在手机查看原设备的连接状态。桌面另需本机已解锁、原驱动可用和准确授权。

**只想把文字工作从 Windows 交给手机？** 支持本档的全新「登记这台电脑的设备身份」安装，
配对页可单独选择 **仅配对 · 手机只核对电脑身份**。不选 Windows 主屏，也不需要工作区。
核对双方完整指纹与有效期并分别确认后，这部手机只能请求电脑身份和自己的签署回执；
不会拿到能力清单、桌面健康或工作区元数据，工具/模型额度均为零，不能读取历史或取得桌面。
电脑是否能把文字工作交给手机，取决于**手机签给电脑**的另一份原授权；双方都只选身份就没有工作权限。
邀请、核对、明确启动和实际手机连接仍是不同步骤。旧安装没有此档，不修改已有伙伴；
上一版 Windows 原生服务会在监听前拒绝该新配置，不会退回全目录。请勿把配置用于未验证的更早版本。

若一开始只准备了设备，原配对窗口和服务结束后，可以回工作台选 **登记第一个工作文件夹**。
只登记机主再次确认的一个本机实体目录；不写源文件、不配置命令、不发出新授权。
已有能力发现权的伙伴可见新增范围代号；文件访问仍按原协议核对这一个工作区的具体授权。
本机旧接口由其独立令牌保护。新增目录换代或变得无法安全核实时，在配对与服务中省略，不改用同名目录。
未核实落盘保留原登记记录，不重放、不回滚；手工配置及其他已有安装不由这个入口修改。
已有配对可核对原控制、文件和仅本机旧服务的实际地址，再显式启动。
这里不代启动具有其他外连路由的配置，不把“已有设置”显示成“手机在线”；
本机停止、部分初始化、其他实例正在运行均不会触发自动修复或重放。
功能需要包含准备页的 Windows 伴侣版本；手机 APK 和源码归档不等于 Windows 安装包。

**不启动服务，核对本机曾配对的伙伴：**在已签名、原伴侣未占用的工作台选择 **查看本机配对记录**。
只显示这次安装能用原 Windows 邀请签名回执核实的本机记录：**本机保留配对** 或 **本机已撤销**。
可点一项查看完整设备标识和证书指纹；短编号只用于找记录。较早、由对方发起或不能完整核实的记录可能不显示；
本机账本不可用不表示没有配对。不检查手机是否保存了配对、收到撤销、当前在线或仍获权限，不启动服务或改动记录。

**以后从 Windows 开始菜单重开：**在已签名伴侣的本机准备页选择 **从开始菜单找到工作台**，
核对本机当前用户的准确位置，再确认创建普通的「PocketWorld 工作台」。不必先配对或启动服务。
入口只打开仍属同一安装、同一发布者的已签名工作台；版本升级可沿原固定入口，另一安装或
未签名版本不会沿用。它不属于「启动」目录、不自动启动或固定到任务栏。只支持当前用户标准、
本机、非重解析的程序菜单；不会覆盖或解析任何已有同名快捷方式。此入口可由机主在 Windows
中自行移除；卸载不会删除其他人的链接，也不替机主重新创建。

**配对窗口已打开却找不到：**机主从同一安装重开工作台，若显示「原伴侣正在使用本机工作区」，
可选 **找回已经打开的本机配对窗口**。先核对本次签名安装、同一用户登录和当前已解锁会话；
再明确点选，才请 Windows 将原配对主窗口带到前面。不会读取邀请或屏幕、延长邀请、确认范围或启动服务。
只有后台服务、独立确认/二维码仍在进行、窗口来自旧版或 Windows 拒绝前台切换时，不会另开配对；
服务回执仍在原通知区域，独立原提示仍从任务栏返回。

手机在 **我的设备 → 配对伙伴** 打开这台电脑。后续有对应权限时，才能在桌面准备页
选择范围并 **连接并仅观看**；点 **我来操作** 才申请人工控制，点 **交还控制** 释放人工控制。页面沿用原
Android 原生桥接和 `desktop.viewer` 设备方法，不另建 Agent 任务或模型工具。

电脑沿用已安装的固定管理入口。打开本机配对窗口：

```powershell
& "$env:LOCALAPPDATA\PocketWorld\Companion\Manage-Companion.ps1" -Action PairDevices
```

配对页与独立的本机指纹确认页按实际显示器、系统正文字号以及任务栏以外的可用区排列。
较矮窗口把「本次邀请」和「手机候选与指纹」并排放置，两栏及最终完整授权原文均可滚动，
可用 Tab / Shift+Tab 在控件之间移动。缩短窗口不隐藏授权选项、不缩小字体或代为确认；
实际放不下完整操作会停止，请在较大可用区重开。本机验证码仍需亲自在原确认窗口输入。

首次配对不必先查 IP：点 **选择本机地址**，从 Windows 当前活动的 Wi-Fi /
以太网私网地址中选与手机同网的一项。只在本机读取网卡，没有搜索手机、联网
测速或开启服务。选中后还要点击 **创建一次性邀请**；若网卡或地址已经改变，
须重新选。特殊网络、没有合适选项时仍可手动输入准确地址。

在电脑选择准确范围，核对双端身份、累计次数和到期时间，完成双方确认后启动
桥接。主屏授权包含当前交互会话所有窗口的观看与人工操作，须在电脑明确确认。
**已有配对不能靠升级自动获得 `desktop.viewer`；旧授权需在电脑重新配对并确认
新的桌面授权。** 仅看到桌面准备入口不代表已经获准观看；缺少原生桥接、媒体依赖或
有效授权时报告不可用。

电脑邀请窗口可显示本次短时二维码。用手机拍下完整二维码后，在 **我的设备 →
配对设备 → 对方已发邀请 → 选择邀请二维码图片** 选中它，再点 **核对所选图片**。
手机只从系统选择的这张本机图片识别原邀请，不申请相机/图库权限，也不保存为附件；
读取不会发送配对候选或开通桌面权限。仍须核对本次指纹与准确授权，原邀请到期须重建。

**电脑主人核对这次桌面连接：**启动原服务时若自行保留「设备工作回执」，在时钟旁点击该入口 →
「这台 Windows 的桌面连接」。它只读取同一原进程中仍获准的直接观看会话：可区分仅准备、
正在协商、Windows 的媒体连接已建立，以及这一次是否确实持有原人工输入租约。需要时可另看本次
核过的设备完整标识。连接或本机近期发送帧都不等于手机已显示、有人在看或键鼠操作已完成；
状态附本机读取时间，需手动重读。原服务忙、暂停、失去身份、传输收尾未知时不把它说成已断开。
这里不抓屏、不读取帧内容、ICE 地址或输入，不联网/续租/传递控制；不查其他软件，也不给未保留此入口的服务新加监听。

**电脑主人要暂停正在使用的远程桌面：**在这台已解锁的电脑再打开一次伴侣准备页。
已配置桌面且原工作区正在使用时，点 **暂停这台电脑的远程桌面** 并确认。它调用原有
`-Action StopDesktop`，不取消命令/仓库工作，不撤销配对，也不会恢复输入。
点 **重新读取本机状态** 可区分「本机已保存请求」与「原执行器已处理这次暂停」。
后者只指原看门狗处理相同编号和相同字节的请求；驱动清理是否核实单列，不能撤回
先前已派发的输入。旧或未运行的执行器可能没有回执；不会补发。恢复仍需本机原
`-Action RecoverDesktop` 的独立核对；重新连接、配对或重启不会重放未知操作。

**两端从原执行设备查工作：**本机配对窗口点击「启动桥接」前可勾选保留
**设备工作回执**；已有配对也可在准备页选择「启动并保留『设备工作回执』入口」。
这里先选方向。**其他设备交给这台电脑** 只列原发起设备直接委派、此 Windows 在自身
工作区已接收的白名单命令与目录、文本读取。对于 `command.run`，本机读取原执行编号、进程状态与留存输出
（最多末段 1 KiB），不连接发起手机。运行中或只有接单记录不算退出；退出码 0
也不等于改仓、交付文件或完成整个目标。手机恢复连接后在该原工作的「查询原操作回执」
核对同一 operation、Windows job 与请求摘要。原结果/授权不在时，不补跑。
手机可以在自己的私人原派单中单独查看它当时指定的短命令别名，不用为此联系电脑。新 Windows
伴侣接过的直接命令可由本机机主另行核对这个别名：仅在原授予、原工作文件和接单时的固定摘要均可核时显示；
旧回执或已不在登记中的别名不猜测。两端都不因此展示其余参数或程序路径，也不交换命令清单。
首次初始化的命令白名单为空；必须已有可用的本机 .exe 白名单及该资源准确授权，
不能把配对当作任意命令权限，不能把手机目录当作 Windows 仓库。本入口不做项目副本生产。

**手机原先交给这台 Windows 的单文件：**仅在原任务已经明确选材、原设备和工作区允许
写入时，现有 `workspace.receive` 可以把最多 256 KiB 的所选文件按预期目标版本投递。
在 Windows「其他设备交给这台电脑」或手机原派发的「查询原操作回执」，可核对是只接单、
在等字节、确定未派发替换、写入结果未知、落盘已核实但传输收尾未确认，还是已完整落盘。
不把原生替换之后的回读/版本异常说成「没写」。结果按原手机任务/轮次、
转移编号、原文件 SHA、Windows 工作区、原生替换与实际回读的字节交叉核对。不重新打开目标
或附件、不补写、不把过去落盘当成今天仍未变。旧伴侣/缺原件仅报可证状态；此入口不会开放
工作区写权限，也不能把本机私有源码补丁自动回传给手机。

Windows 工作区新留存的文件版本由本机 Win32 原始目录与文件句柄绑定，按实际字节比较，
不从旧路径缓存、同名工作区或替代文件拼回。差异页对两侧都按相同 UTF-8 规则读取，
不把 Windows 原本相同的 CRLF 文本误报成改动。每个原路径保留最近八个，
本机私有缓存的总体目标为 256 项（单项 256 KiB）；另有一个待收尾位置，未知对象不会被当作已释放。回收只限能核实原生身份、
创建时间、长度和 SHA 的本机派生缓存，不删除工作区的文件、旧缓存或无法确定的替代物。
工作区实际已读回成功与这份额外版本能否留存分开记；旧回执不补造留存证明。

**Windows 机主看这次收到的文件：**打开通知区域「设备工作回执」→「其他设备交给这台电脑」→
原手机 → 选中该次文件投递 →「在这台电脑查看当时的原文件」。只有原落盘回执、当时的独立留存、
同一设备授权和当前工作区读取范围均可核对时才读。原留存被轮换后，即使同路径后来
重现相同字节也不作替代。小型可显示 UTF-8 文本遵守原 `workspace.read` 的 24 KiB
控制回包上限；其他文件须有同范围尚有效的 `workspace.export`。只留写入权或过期后
只许查询操作时，仍可查原回执，不能查看正文。原生只读窗口用文本或完整十六进制展示有界
原件，锁屏或失去原权限时关闭，不读现在的目标、不启动文件关联、不提供手机端的历史文件下载。

另一个按钮 **在资源管理器选中工作区原文件** 核对的是现在的原落点，而非留存。
只有该次原写入曾记录写后读回的精确父目录和文件身份/创建时间、原设备至今还具有
该工作区的定位、列目录和读取文件权限，才可在机主点选后核对。被移走/替代、身份不足、
现有原文件已改变、私有状态树及其上级、快捷方式/可执行或未知类型，都不改开其他位置。
通过后资源管理器仅展开已获准的父文件夹并选中所交付的普通文档、图片或 ZIP；
机主也会看到同目录的其他条目。与伴侣的只读窗口不同，已打开的系统文件夹由机主管理；其后撤销配对不会关掉它。伴侣不触发文件关联、执行、写回或传给手机。

**手机从这台 Windows 取文件：**在「设备工作回执 → 其他设备交给这台电脑 → 原手机」
选「手机请求取走文件」。它与“接收所选文件”方向不同：手机的原任务请求的是该 Windows
工作区已有的普通文件。窗口按原操作、原手机任务及轮次、Windows 工作编号和固定导出登记核对。
若原权限仍允许查看这份文件的说明，可核对当时冻结的文件名、字节数、SHA-256、文件与传输编号，
并区分“本次仍见原缓存登记”和“仅有历史发布记录”；两者都不代表手机已下载。
只有手机对原固定版本验完字节并登记到原任务附件，才算在手机收妥。
撤回、权限或原证据不足时最多显示操作记录；不读取当前工作区、补发或重新导出文件。

**手机一侧核实工作区导出的到件：**在本机私人原任务的「设备 → 原派发」选择这次直接
`workspace.export`，点 **只查这台手机的原附件**。不要求电脑在线：从此手机已验证的
原操作、执行轮次和对端固定文件描述符，定位同一 AttachmentBook 中首发登记的单项。
只有原私人记录、来源、发布计划、整个文件的大小和 SHA-256 都匹配时显示“本次已核实”。
只有描述符、现无登记、被撤下或字节不符时分开提示；不扫描同名文件、不重新下载或向电脑回报。
本次核实到原件后，可点 **在原工作中打开这份文件**。短时本机句柄只绑定这一笔原派发；
点击先复查同一件，再进入同一私人任务，用既有原格式查看器复检附件范围、固定版本和真实字节。
从这个入口只能阅读或返回原任务，不展开附件库，不调用外部阅读器或分享，也不恢复到另一个任务窗口。

**机主对照一次手机请求的 Windows 文本读取和一份本机源码副本：** 在该原读取回执点「对照这次读取和一个本机源码副本」，再选本机已保存的副本。只有原操作/轮次、仍可用的原读取与位置授权、当初同一工作区的物理身份、原副本清单和准确文件路径都能核对，才报告当时两个版本的字节数及 SHA-256 是否相同。不读取现在的源文件，不检索其他项目，不推断手机当时使用了该 Git 提交，也不把本机结果发给手机。旧副本没有原工作区出生身份时不回填、不按路径名猜。

两个原版本的完整摘要和长度相同，且目标是机主副本的一份 ≤32 KiB 普通文件时，可另选 **单独在这台电脑起草这个文件的补丁**。机主确认读取本机完整原文件后，重新核对 Git 原提交、原副本中同一文件的物理身份和字节；编辑界面不使用手机回执节选，不提供改选路径。保存前再确认原任务、已配对设备及两端范围。草稿及另存的补丁属于机主本机，不写仓库，不归入、推进或回传手机工作。

原差异文件确已保存后，机主可以另选 **只在这台 Windows 记住此关联**。以后在同一次原读取上
点 **查看机主为这次原读取标记的本机补丁**，不必猜是哪份底稿。此书签不进手机工作记录，不表示交付。
读者必须仍有原读取及位置授权；选定后再次核对原任务/轮次、工作区、底稿和实际补丁，不从同名文件、
相同摘要或现在的源码推断关系。没有书签不表示没有本机工作。

**不配置命令也能核对原工作区读取：**实际已批准当前工作区读取范围时，Windows 原本就能
处理 `workspace.list` 与 `workspace.read`。两端可查这次操作当时收到的相对路径、目录
返回数量与前 8 项，或该 UTF-8 文件当时的版本、字节数和开头最多 1 KiB。原执行端在首次
返回时把原路径和准确结果的摘要固定到同一操作。历史页只看那个仍保留的工作；没有
重新扫描目录、打开源文件、跟随重解析点或生成可编辑副本。旧版、缺原件或摘要不符不冒充
已核实的目录/文本。这条路径不需要授权任意命令或写权限。

**这台电脑交给手机** 是另一方向：
在这次原服务运行期间，从 Windows 时钟旁的通知区域（含折叠图标）可反复打开。
选同一已配对设备及此前从本电脑发出的原手机动作任务，方才向那部手机读取。
本机派发记录、原手机当前任务状态与接收端已核实的成果分别显示；离线、授权到期、
身份改变或旧端不能核对时，不以旧状态冒充结果。窗口只短时展示原授权下的回执，
关闭不改任务。两个方向都不是远程桌面或手机全部工作列表，也不能派单、接管或恢复；
不启用 Windows 登录自启动，没有新的 Web 端口、后台轮询或系统权限。

## 三路能力怎样协作

| 路径 | 当前实现 | 返回什么、何时使用 |
| --- | --- | --- |
| agent-desktop 结构化执行 | 固定源码的 Windows headless CLI；读取 UIA，使用原生元素引用点击或替换完整值 | 精确窗口默认 `semantic`，返回有界结构与引用，不截图。目标不完整、歧义或引用失效时拒绝执行。 |
| Cua 视觉执行 | 固定 Cua Driver，沿用已有桌面适配器 | 显式 `hybrid` 返回结构与 PNG；`visual` 返回 PNG。主屏默认 `hybrid` 的窗口目录不等于窗口内部 UIA 树。视觉操作必须有对应的新观察。 |
| 人工桌面视频 | Companion 内 aiortc/PyAV，浏览器接收单向视频；授权窗口使用原 HWND 捕获 | 向手机用户传送桌面画面。视频不会成为模型图片，也不刷新 Agent 的结构化观察。人工输入仍走原 mTLS、授权、租约与持久操作记录。 |

结构化路径不保证每个应用都有可用 UIA；大型或自绘界面可能需要显式视觉观察。
默认窗口观察只在原生树明确返回 `elements_complete=true`、且没有截断或身份
缺失标记时可用于结构化输入。仅安装 Cua、无法证明树完整时会明确拒绝默认
`semantic` 并提示显式选择 `hybrid` 或 `visual`；不会凭空补出完整性证明。
结构化点击结果未知时，不会自动改用坐标点击。三路实现的精确契约分别见
[AGENT-DESKTOP.md](packaging/windows/AGENT-DESKTOP.md) 和
[DESKTOP-STREAM.md](packaging/windows/DESKTOP-STREAM.md)。

若 Windows 已完成观察、手机却没有收到回执，原任务可用原操作 ID 查询：
能核对同一设备实例、授权范围、任务、操作和原件摘要时，返回**当时**的结构，
或固定到当时 PNG 的描述。默认即使不能使用图片模型也可查询状态；需要原图时，
在同一 `device_operation_get` 设置 `includeOriginalImage=true`。只有手机在
原有效期内取回并核对实际字节、尺寸和
哈希，才可把旧图作为参考交给本轮模型。不会重新截图、续租或占用新的观察次数。
回查只废弃同一张图的旧输入引用，不改变现有租约，不撤回已经发送的输入；
继续点按需要新观察及原有控制授权。旧版本没有原件摘要、原件缺失或授权不再
允许读取时，不补造画面。若仍有状态读取权限，可查原操作状态；已撤回的结果不返回。

人工接管等待当前有界 AI 操作结束，且不能强行覆盖未知状态或其他所有者的租约。
人工租约与视频会话最长五分钟；交还后，AI 必须取得新租约和新观察才可继续。
每次人工输入引用最近两秒内的真实发送帧。Companion 在原帧最后一个 RTP 包
完成发送后发布实际 `rtpTimestamp`；手机必须把它与**当前显示帧**的视频回调
时间戳逐一匹配，才开放输入。媒体与元数据可按任一顺序到达，但旧帧、相同尺寸
的其他帧、AV PTS 或重传不能代替这条身份对应。浏览器缺少该回调字段、媒体
实现校验不匹配或帧过期时保留观看并禁用输入。

派发前还会重新核对原进程、窗口、显示器、前台与物理几何，使用原 Cua capture
身份映射坐标；DWM 窗框裁剪只有可唯一映射时才允许点击。上述对应证明输入
引用了用户实际显示的编码帧，不证明截帧之后桌面完全没变，也不证明业务目标
已完成。接管、交还和输入会废弃旧观察与可操作帧，要求后续取得新证据。

最多两个窗口可同时观看，只有一个可持人工控制权；另一个窗口显示“另一窗口
正在控制”。滚动针对当前前台的授权 HWND，使用原生窗口滚动路径；不接受网页
自填屏幕指针位置，也不继承旧点击位置。支持有界点击、滚动、文字和有限键盘
输入；本轮不提供拖拽，也不宣称硬件加速已完成。

**人工输入消耗原 PairGrant 的 `toolBudget`，与 AI 工具共享同一有限次数池。**
计费点是原操作账本持久占用输入尝试的身份，操作占用和扣次数在同一事务中
完成；已占用的失败或未知输入保留占用。观看、查询状态不消耗
这项输入次数；新 viewer、操作 ID、任务或授权代次不会重置原池。重复操作返回
同一运行时保留的原回执，不自动再次派发；回执缓存丢失或重启后明确报告结果
不可重放。撤销、到期、锁屏或本地停止终止可用会话；只有
`inputReceipt.status=completed` 且 `inputDispatched=true` 才视为已确认派发。

人工点按、滚动或发送文字后，如果手机没收到确定回执，**先留在原观看窗口，点「核对这次输入」**。
支持此项的伴侣通过原会话的 `status` 返回该会话最后一次人工输入的有界回执。手机只显示能对应
这次手势、原操作 ID、请求摘要和原视频流的结果：已派发、确定未派发或仍不能确认。
已派发不证明应用已保存或完成业务操作。核对不会重发输入、续租或解除本机待核对状态。
旧伴侣没有声明这项能力、回执缺失、会话关闭或重新连接都不能补造原回执；此入口不是任务历史或截图回查。

结果未知时，本人仍可明确交还或关闭页面，但全局 `needsReconcile` 不会因此
消失，其他窗口也不能借新会话接管或继续输入。关闭只释放本会话已结算的安全
租约；仍在执行、结果未知或本机暂停的资源栅栏保留。升级旧主干版本时，旧
操作 ID、查看会话 ID、已消费额度和原资源栅栏同样保留，不能因换了账本入口
而重新执行；旧记录不被改写为“已确认无后续输入”。

连接从打开请求到第一幅实际播放画面最多等待 45 秒；已经播放后持续停帧，
给予 10 秒恢复窗口。视频轨道结束或元数据通道关闭时关闭准确的原会话；
短暂 mute、断线和重新连接期间禁止输入，恢复后要求新的画面证据。缺少可验证
RTP 身份但视频仍在正常播放时保持仅观看，不会把“不能接管”误判为“视频卡死”。
浏览器同时缺少帧回调和解码帧计数时，仅用递增播放时间维持观看；它不能证明
新像素已经显示，也不作为帧新鲜度或输入授权的依据。
用户手势在等待状态查询前固定它对应的画面与控制版本；等待中画面或控制权改变，
该次尚未发送的输入就取消，不改绑到新画面，也不标成已发送但结果未知。

## 网络与捕获范围

默认 `desktop.streaming.iceServers` 为空，以双方直接可达的 LAN 为基础，没有
内置公共 STUN/TURN。跨网络需要自行配置合适的 ICE 服务，并保证原设备信令与
输入通路可达：直接双向 TLS，或已有 WSS 字节中继承载的内层双向 TLS。
**TURN 只解决媒体路径，不替代配对授权和原 mTLS 路由。** LAN 连通不代表任意
NAT、防火墙或外网组合都能连通。

视频没有独立的未认证 HTTP/MJPEG 入口，也没有输入 data channel。默认长边
最多 1200 像素、10 FPS，最多两个观看会话；当前使用软件编码。窗口授权只捕获
原 HWND，不扩成包含其他窗口的屏幕矩形；整块主显示器需要对应主屏授权。
当前仅支持 Windows 交互用户会话与主显示器；锁屏、UAC/安全桌面、跨主屏边界
窗口和非主屏捕获不在本实现支持范围。受保护或特殊渲染窗口可能显示空白。

## 固定来源与 Windows 三二进制打包

### 在准备好的构建机一次检查，再明确做本地候选

该仓库本身**不是**一个开箱可装的 Windows 包。没有自行安装编译器、联网取 wheel/驱动、生成可信
输入锁或代签的步骤。构建者需要已完成独立核准的完整 Windows x64 Python 输入锁和 SHA-256、
匹配的隔离解释器/完整 wheelhouse、两份指定提交的干净上游 Git 仓库，以及带离线缓存的 Rust/MSVC。
现有几个组件锁不能替代整份输入锁。普通电脑使用者不需要准备这些，应该取得独立 Windows 发行物。

**没有独立整锁时，先交什么材料？** 普通用户不需要运行这一步。
维护者可以在隔离、已准备好的 Windows x64 构建机，用明确选定的**基础 Python**（不是 venv 的解释器）采集一份待审核报告。
目标环境、wheelhouse 与源码目录互不包含，输出为这些目录外的新 JSON；输入树须在采集期间防止其他写入：

```powershell
& 'C:\BuildInputs\Python\python.exe' -I -S -B .\companion\packaging\windows\observe_runtime_inputs.py observe `
  --base 'C:\BuildInputs\Python' --venv 'C:\BuildInputs\CompanionVenv' `
  --wheelhouse 'C:\BuildInputs\wheelhouse' --report 'C:\BuildOutput\runtime-observation.json'
```

报告列出该解释器、venv 启动器、Python 许可、两棵本机树的实际摘要，以及每份 wheel 的名称、版本与字节摘要。
工具从同一普通文件句柄比对已装包与所选 wheel 的元数据；不运行 venv/.pth、编译器、驱动或伴侣，不安装或联网，不写入输入目录。
整个目录不是原子快照，运行时依赖兼容和真实 Windows 执行仍待原构建阶段验收。
**报告不是输入锁**，不能传给 `--input-lock` 当作批准，也不提供一键转换。发布维护者应与供应方资料和独立受控镜像核对，另行给出正式整锁及独立通道核准的 SHA-256。
已有整锁时用 `compare` 替代 `observe`，另传 `--input-lock` 与 `--input-lock-sha256` 并使用新报告名，可查具体哪项树、解释器或哪份 wheel 不同；有差异返回非零。报告一致仍不等于已构建或签名。

在干净的产品源码根目录，用该已准备的解释器运行：

```powershell
# 这些值来自已核准的材料，不是在这条命令中把当前目录或当前环境自动当作正确答案。
$inputs = @(
  '--source-commit', $productCommit, '--version', $bundleVersion,
  '--cua-source', 'C:\BuildInputs\cua', '--agent-source', 'C:\BuildInputs\agent-desktop',
  '--input-lock', 'C:\BuildInputs\windows-runtime-inputs.json', '--input-lock-sha256', $runtimeLockSha256,
  '--wheelhouse', 'C:\BuildInputs\wheelhouse', '--output', 'C:\BuildOutput\candidate-new'
)
python -I -B .\companion\packaging\windows\build_candidate.py check @inputs
# 只有要真正生成本地未签开发候选时，才另外显式调用：
python -I -B .\companion\packaging\windows\build_candidate.py build-development @inputs
```

`check` 逐项报告材料是否齐备，不写输出、不启动驱动或构建。它不能证明 Cargo 缓存、
MSVC SDK 或 GUI 可用。显式 `build-development` 通过相同检查后依次调用原两份固定源码的驱动构建、
原 PyInstaller/内置媒体校验及原打包器；最后从实际 ZIP 回核长度与 SHA-256 才写 `candidate.json`。
输出固定标为未签开发候选，不生成正式首装材料、不安装或运行伴侣工作台，不推送。中断会保留
阶段目录给构建者检查，不接着跑、不覆盖；原始构建记录含实际构建时间，不承诺逐字节可重复。
上游构建脚本不是系统网络沙箱；需要物理离线时由专用构建机提供。

### 从本机候选中准备准确的待签文件

已经生成过 `candidate.json`，不需要为了把文件交给有权限的发布者重跑编译。构建者在受控
Windows x64 电脑选择原记录，另行提供已经核准的原 ZIP SHA-256 和源码提交：

```powershell
$select = @('--candidate','C:\BuildOutput\candidate-new\candidate.json',
            '--expected-zip-sha256',$approvedCandidateZipSha256,'--source-commit',$productCommit)
python -I -B .\companion\packaging\windows\prepare_signing_inputs.py check @select
# 只有明确要另存这组材料时才运行（未占用的新目录）：
python -I -B .\companion\packaging\windows\prepare_signing_inputs.py prepare @select --output C:\BuildOutput\ToPublisher
```

`check` 用同一个只读文件句柄核完整候选 ZIP、三份构建凭据以及每个待签成员的实际字节；
不会打开程序或写目录。`prepare` 仅另出原 Companion、两个原驱动、四个原管理脚本，
回核后附 `signing-request.json`。不含其他运行时、私有配置或证书。它是**签名前的材料**
而不是签名完成凭据或可安装包；不会挑选证书、签名、上传或自行联系签名者。
独立签名后，最终文件仍须由原正式打包器逐项验证，不能把此请求改名代替签名结果。

### 用发布者已经签好的原返回包组装，不覆盖未签候选

此步骤**不能签名，也不能代出签名证明**。在受控 Windows x64 构建机，使用与原候选相同的准确干净
产品提交。发布者已独立完成签名后，准备一个单独的本机返回目录：`app/` 是签好的原 Companion，
`driver/` 是签好的两个原驱动，`tools/` 是签好的四个原管理脚本，根目录是发布者交回的
`signing-provenance.json`。该回执沿原正式打包器的 `pocketworld.windows-signing.v1` 格式，
仅含 `format/sourceCommit/complete/artifacts`；七个准确路径各含 `unsignedSha256/finalSha256/signatureStatus/signerThumbprint`。
原待签 `signing-request.json` 可原样附在根目录，但不是发布者回执。不要用自己写的回执或从同一返回目录抄出的值充当独立核准。

```powershell
$selection = @('--candidate','C:\BuildOutput\candidate-new\candidate.json',
  '--expected-zip-sha256',$approvedCandidateZipSha256, '--source-commit',$productCommit,
  '--signed-return','C:\PublisherReturn\original-seven', '--receipt-sha256',$approvedPublisherReceiptSha256,
  '--publisher-thumbprint',$approvedWindowsPublisherThumbprint)
python -I -B .\companion\packaging\windows\assemble_signed_candidate.py check @selection
# 选择另存本机完整发行候选时才运行；必须是全新的目录：
python -I -B .\companion\packaging\windows\assemble_signed_candidate.py assemble @selection --output C:\BuildDelivery\new-kit
```

`check` 不写产物：复核原候选、未变成员、外部批准的回执摘要、七对签前/签后字节及 Windows 对准确
发布者的真实签名判断。签前到签后的对应关系来自**有权限的发布者的原回执**，单凭同一签名证书不能证明来源。
`assemble` 在新位置沿用已有正式打包器，另读回最终归档，并检查七个已签文件以外的所有原成员均未改变。

机主在**同一个完整源码副本**中分别起草并明确另存的文件补丁，也可加入原多文件交付。清单标为「机主草稿」，表示建议的目标内容，而非工作树已被修改；与已有新增、修改、建议移除共用同一组 2–8 件核对、路径冲突、原件字节和另存确认规则。对同一路径的不同草稿必须取舍。不能利用这个入口混入其他副本、其他提交，或将各自只授权保存一个文件的独立副本拼成整仓。

机主可在**已经保存的整项目副本 → 在原项目中查找一段文字**中查找类名、调用或短文本。从原清单选一个目录的直接普通非执行文件，可逐项指定，限 32 份、每份 64 KiB、合计 1 MiB；查看准确文件名并确认才读。只在本机查固定大小写的字面文字，不递归，不扫工作树，也不能从单文件副本扩张范围。逐件重新核实文件出生身份、原字节 SHA 和 Git blob；改换、未核实或不支持的文件不算作无命中。显示实际命中行数，最多列前 80 行；点中再核原文件并在原文中选中该处。不创建索引文件、不存查询、不联系手机或模型。

2–8 份已有原补丁。仅接纳同一私有副本/原提交中互不冲突的路径；若同一路径有多个版本，

**为新文件起草源码提议**不要求先用外部编辑器把文件写进副本。机主从已保存的整项目副本输入原有父目录下的确切新源码路径；核对原提交父树，以及本机原副本父目录（不递归）的完整有界名称清单与 Windows 大小写/规范化别名。再从空白稿按 UTF-8 无 BOM、LF、普通文件 100644 起草、核对完整新增差异；明确确认才另存新的本机 `change.patch`。原工作树未检查，拟议路径并未创建；不是从现存的新文件读取，也不与该类补丁混淆。四个单独的原记录位置，不覆盖、执行、应用或发送。
