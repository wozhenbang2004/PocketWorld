# PocketWorld：在自己的设备之间持续工作

产品决定（2026-11-19）：不是 Android 向电脑投屏，也不是每个终端把全部资料送到供应商的云。用户拥有自己的手机、Windows、Apple 设备与 Linux 主机；安装各自的入口后，可以建立互信、选择能力并交办。默认可不使用云。用户可为某个工作区指定主 Agent，设备仍保有各自的数据和执行权。

## 三个不混用的概念

- **入口**：人从哪台设备输入、看进度、决定、读成果。切换入口不转移代码、执行进程或历史。
- **协调者**：谁把目标拆成可交办步骤，向本人选定的设备索取能力与回执。主 Agent 不因此取得设备管理员、全文件、全屏或发消息权限。第一版由用户显式选主，不自动选举；换主不能重放已经接纳的请求。
- **执行者及数据驻留**：在哪台设备真实运行，在哪台机器的哪些文件上做，任务由哪个原生账本记录。跨端默认只携带工作/操作身份、进度、错误和获准交付的固定文件，不默认镜像消息、记忆、凭据或整个磁盘。若任务选了远程模型，批准给该模型的必要输入仍可能发送到它；连接拓扑、模型选择和资料留存分别显示和控制。

目标体验（尚未交付）：从 Android 给配对 Windows 一个开发目标，指定 Windows 上自己的工作副本。Windows 接纳、执行并保存修改；桌面打开其已接纳原任务。手机返回读取同一操作的结果。如果项目在安卓本地，不能把“能看原任务”变成能读手机仓库。迁移文件是独立的本人操作。

## 连接选择

1. **同网直连为首版默认。** 发现设备后仍要核对配对身份。配对、可查看、可调用/可写分别说明。没有合适授权时，显示由哪台设备的本人处理，不为新能力借用旧权限。
2. **异地是可选路径。** 优先用户已建立的私网；需要中继时，明确中继只转发连接，不成为任务、文件或记忆的默认数据中心。不可达与任务失败分别显示。
3. **自带服务器既可做节点，也可做自选常驻协调点。** 每个工作区明确数据留在哪里，并可以撤销授权。普通 SSH 主机只说明已有连接能力；启动持久 Job 需要实际 Companion。平台不代买、不默认托管、不把 BYOS 作为移动端或同网使用的必选条件。

### 连接首次验收与平台许可

- 先验不依赖白名单程序的链：Android 只读取机主已批准的 Windows 工作区内一个 UTF-8 文本；Windows 查看本次留存的原回执，手机断线重连后看同一操作。对照原版本和摘要，不因重新打开回执再次读取源文件。反方向需要具备相同无屏能力契约的构建，不能拿只有收回执的旧 Windows 入口当成能派活。
- 先保证同网直连，再单独验用户已有私网。异地控制通道与屏幕画面是两条链路；控制走通不代表画面可达，Wi-Fi 与蜂窝切换后要重新核对**同一个**原任务，而非再派一次。
- 当前 Android 发布配置目标是 API 35。升级目标到 API 37 时，要适配 Android 的局域网许可及按单个服务选择的系统入口；Apple 的 Bonjour 仍要按 Local Network 许可设计，iOS 自定义组播／广播另有权限要求。保留二维码和手工配对作为发现替代，不视为绕过网络授权；用户拒绝网络权限与对方实际离线要分开显示。参考 [Android 局域网权限](https://developer.android.com/privacy-and-security/local-network-permission) 和 [Apple 本地网络隐私](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy?language=objc)。

## 谁做主，设备掉线后怎么办

- **主 Agent 按工作区设置，不按登录账号强制唯一。** 同一对设备可以在家庭工作区由手机协调，在开发工作区由自己的常驻主机协调；首次使用仍可在本机独立办事，不必先选主。
- **能力目录不是授权。** 每个执行设备声明自己目前能做什么，区分“未配置”“未授权”“目前离线”。协调端只从本次允许的设备和能力中挑选；执行端在实际接单时确认范围和到期时间。不能以离线设备的身份改派，也不能把原任务的文件权限借给替代设备。
- **接单前、接单未知、已接单是三种状态。** 接单前可编辑或换目标；结果未知只向原设备核对，不自动再提交；已接单后由执行端保存原任务、结果和可用停止入口。换主只改变以后由谁协调，不重放既有任务。这个流程不要求所有终端一直在线；也不承诺每种任务都能从执行机重启后恢复。
- **跨机总览只读已授权的摘要。** 未配对设备只能看自己；配对后也不默认开放任务内容。UI 把已接纳、正在处理和成果可读分开，缓存的旧回执附上最后核对时间，不拿网络可达、进程退出码或协调端说“完成”当作工作完成的业务证据。

## 落到现有实现，不重造第二套任务系统

当前跨设备原生消息已区分发起者、当前调用者、目标设备、原根任务和本次操作，并已有精确范围与去重。后续工作区选主应当把这些已有能力串起来：保存这个工作区接下来选用的协调设备，而不是去改已发出的身份、复制远端任务表，或把现有单次执行版本当成整个工作区的主从世代。

首版选主只需解决“从下一个任务开始，由谁协调”及“离线时看到待处理状态”。没有足够证据确认旧设备接单与否时，不开放自动接管。先做两台设备都能准确找到同一份原工作；同一条记录在各端展示应该一致，但不要求各端缓存相同的数据内容。

## 产品分段与可验收下限

- **第一里程碑 Android ↔ Windows。** 先用 Windows 获准的原目录／文本读取；机主已有明确白名单时才验有限命令。反向先用交给 Android 的纯文字目标，真机验接单者、原编号、断线重连、产物或结果与停止状态，拒绝授权、改绑也不能自动转派。然后补 Windows 原本机项目生产：在 Windows 的独立工作副本改项目、预览差异、交付固定结果。当前 Companion 的项目副本生产依赖 POSIX，普通命令、配对与远控只证明各自能力，不等于 Windows 原生项目生产已经可用。
- **第二里程碑可选 Linux 常驻点。** 原节点在不依赖入口在线时继续执行；若协调端断线，已接纳工作仍继续，未接纳只保留待处置而非假成功。首次查看、重新连上、协调者变更、原件交付分别验收。尽量复用现有的身份与授权，不新开全设备管理员模式。
- **第三里程碑 Apple 和桌面扩展。** iPhone 先交办、批准、看结果和系统允许的动作。macOS 可在得到真实平台依据后增执行能力，不从 Android 规则外推。Windows 完整工作台可沿用共享前端与原任务协议，原生文件、窗口、权限及更新由各平台宿主提供；不另造一个全量同步账本。

验收时记录发出端、执行端、原操作和本机任务四者的对照。Windows 白名单命令先用机主配置的无外部影响命令；可达、被授权、被接纳、真正执行和返回结果各自有证据。桌面独立改项目是下一道验收，不得用同一个命令的退出码代替代码差异或固定产物。

### Windows 本地开发的落点

现有 `WindowsBackend` 和 `WindowsWorkspaceFiles` 已提供基于真实 Win32 文件句柄的本地工作区读取，以及 Windows 进程管理；项目生产入口却在 `harness_registry.production_available` 和项目副本模块内明确只支持 POSIX。不要把判断里的 `os.name` 移掉来“开通”，也不要把对仓库的全权 shell 当替代。

桌面机主先选出本机仓库，不允许手机传任意本机路径。第一版生产只接桌面登记的 Git 仓库，确认原版本与目标，创建可复核的私人副本；Agent 在 Windows 上运行、在副本中修改，Windows 留差异和可独立核对的成果，原仓库保持不变。完成这些条件才公布“能改项目”。路径、启动、停止、产物分别用 Windows 原生证据验，不能把 Linux 的构建或原白名单命令成功当这里的验收。

视觉：一个“我的设备”入口，默认只露名称、连接状态、实际可用下一步；技术地址、证书、工作目录和详细授权放在详情。工作概览显示执行位置，不用打开发起对话才能猜是谁在做。遵循审美库的角色清晰、渐进披露、原位返回与真实反馈。以上是设计与验收线，不是现有跨端真机通过的声明。

对标：[Apple Continuity](https://support.apple.com/en-gb/108046) 的换端继续、[KDE Connect](https://apps.kde.org/kdeconnect/) 的设备互通、[OpenClaw 节点权限](https://docs.openclaw.ai/gateway/pairing) 的配对能力，以及 [Grok Bot 的桌面成果阅读](https://docs.x.ai/grok-bot/files-and-results)。自带服务器行为另见 [Muse / Grok Bot 下限](byos-muse-grok-20261119.md)。
