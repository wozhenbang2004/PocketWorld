# 自带云主机工作台：Muse / Grok Bot 体验下限

用户要求：对标 Meta Muse 和 xAI Grok Bot；PocketWorld 不代买、托管或内置服务器，但用户提供自己的主机，接入后像内置一样交办，不是每次进 SSH 终端。调研为官方公开资料与本仓库源码，不声称使用过他们的私有 API、跑过实机或知道其未公开实现。

## 确认要复刻的体验

| 旅程 | Meta Muse | Grok Bot | PocketWorld 的下限 |
| --- | --- | --- | --- |
| 一句话交办，离线也继续 | 每人一台隔离、持久的 Linux VM，含完整浏览器，关 App 后仍工作，必要时人能介入。 | 持久有名 Bot 接收责任；使用云电脑里的浏览器、文件、终端，用户离开工作不停。 | 首页用自然语言交办。已配主机默认显示为一次可选工作位置，不要求用户写 SSH 命令或反复配置。只有主机端有真实任务接受/执行回执才写“在主机上运行”。 |
| 回到同一件事 | 文件、工作环境、连接持续存在，用户可在原任务接手。 | 一个账号的 Bots 可在同一台持久电脑上交接文件；各屏是独立操作面，不是独立权限边界，登录与凭据按其模型会共享。结果进文件和原对话，用户可打开回用。 | 断网不当失败且不盲重试。回同一任务、日志游标和固定成果；查询状态与重启任务是两个动作。可停可核对。 |
| 长期责任 | 官方描述可用 cron、定制技能与子代理。 | 一次提示、技能、定时或事件例程分别对应不同持久范围，Bots 可把分工交回。 | 常用技能与明确授权后才有的定时工作分层。任务和例程不偷用另一个 Bot 的密钥、设备或额度。 |
| 身份与可控性 | 执行容器和凭据服务是不同信任域，外部动作可另行审核；有安全凭据存储。 | 用户可查看、控制云电脑，配置连接器及执行审批；Bot 在线不等于它有任何权限。 | 主机身份、工作目录、项目权限、凭据各自明确；只能访问明确选定范围。手机、Windows GUI、裸 SSH 与云运行环境不混成同种状态。 |

## 我们实际有和实际缺的

- 现有 SSH 持有主机/用户名/工作目录绑定，有命令会话、PTY、SFTP 和本机原回执。关闭连接时原生可明确给出“远端是否结束尚未确认”，不能从这层冒充持久的云 Agent。
- 仓库另有远程伴侣与可核对的 managed sessions 路径。伴侣公开能力当前明确把持久 Job 标为可用、把内建进程沙箱标为未提供；会话目录只是上次本机观察。这是候选接法，不用网页文档或类型字段替代验证，需要逐一证明长期进程、重连和产物属于同一原任务。先复用能满足契约的路径；旧 SSH 主机仍可使用原能力。
- 地址仅确定去哪里。首次还要核身份、授权与选定目录。如果该主机没有已就绪的运行器，界面给清晰准备状态，并在本人明确允许时才进行配置；不把未授权路线变成自动安装、开放端口或持久凭据读取。
- “云主机 ready”分开表示 **能连接、能接持续工作、能查看浏览器/屏幕**。现有 Cloud/Windows/Phone 能力不混报。

## 产品落地顺序

1. **可用位置。** 从用户已授权主机绑定入手，登记一次，显式选本机或该主机；显示服务器身份与能做什么。普通 SSH 模式继续提供命令/取文件，没有运行器时不显示关机后继续的承诺。交办对话不需要另开控制台。
2. **持久执行与交付。** 用原先已获准的工作范围登记身份、启动凭据与事件；首个验收任务从云工作目录本身生成一个实际文件。退出并断网重开，仍读取同一任务的日志、退出状态和固定文件；明确暂停/停止以远端回执核对；不可把旧记录重派。浏览器/设备按原权限分别补。
3. **长期助手组合。** 以真实手动交办链通过为前提再做常驻身份、团队分工、技能与例程。多 Bot 共享主机可以，不应共享无限权根、未经允许的凭据或任意跨项目读写。

交互沿用管家现有工作席与十五项审美主档：一个中性主机身份行、一个可用性结论、一个当前动作。完整指纹、日志、路径、授权和故障按需展开。真正的验收是在一台本人授权的测试主机上，交办步骤没有 ADB，退出 App 后继续并调回原结果；目前未做这个实机验证。

### 第一版入口实施范围

管家/对话中的「工作设置」可将当前目标带去现有 Companion 连接。首次未配置时去原连接设置，已配置时由主人选实际远程工作环境。目标只在手机当前页面间递交，原草稿保留；附件、引用不自动复制。工作区已有不同草稿不覆盖；填入目标仍要经过原运行器、工具和授权审阅。这次不新增地址协议、不自动安装、不主动联系服务器；配置主机成功不代表持续执行或浏览器已验。

本轮执行端做过一次隔离的手动核对：在开发环境中启动实际 Linux Companion，只监听回环地址，以固定命令生成 29 字节文件。第一次请求收到排队回执并关闭请求；另一个请求进来时同一 Job / operation 已完成，退出码 0，原产物读取回执的 SHA-256 与工作目录文件一致。证明实际服务不依赖该客户端请求保持连接；同一个 Companion 在完成之后重启，仍能按原 Job 与 operation 读回，下载字节和原文件完全一致。没有验证正在执行时服务器重启、Android App 关闭、外网延迟、模型执行或浏览器接手。

同一 Linux 目录及原服务账本的两次实际 Companion 启动还核对了：已保存的工作位置指纹相同，每次服务实例的现行绑定不同。因此可记住的是“原来的工作位置”，不是让上一次审批跨服务重启继续生效。

从管家草稿点击核对已保存主机，只做一次现行环境读取；身份、目录和所选执行器重新吻合才选回原位置。空白远端草稿可直接带入目标；已有不同目标不覆盖。已读不启动、不自动探测模型，不跨过传文件和执行的原审阅。
