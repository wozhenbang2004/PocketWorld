# 在阅读页引用已经选中的那一处

基线 `180fcfa`：「阅读与选字」仅能复制；改走消息菜单「引用到草稿」要重选，短消息还会默认选中全文。现在从真实消息打开阅读页后，进入「选字」选定原文，可直接点「引用到草稿」。不用关掉阅读页、再读另一块文本或先粘贴到输入框。格式化阅读和嵌套表格只保留原来的复制能力，不把渲染后的文字冒充原文。

**交互与数据边界。** 控件在点击时读取只读文本框的起止位置，不搜索字符串。用已有 `messageQuoteRange` 映射换行与 UTF-16 边界；宿主返回的全文、当前可见字串和区间必须一致。宿主按消息 / 原文修订 / 草稿窗口再校验，仍由原有 `messageQuote.stage` 登记来源，只有同时收到选区核对与草稿登记回执才显示成功。正文不拼接、消息不发送；未收到明确回执不自动重试。查看、选择或退出本身不把来源注册进草稿。

依[十五系统](https://chatgpt.com/space/page_6c522c5579c08191944bb585f4bf5708)和[项目设计规范](../DESIGN.md)自检：
- 配色与表面、形状与圆角、阴影与材质：复用阅读工具条的同一按钮样式；正文不增加卡片。
- 空间与密度、排版与可读性、跨尺寸与输入：只在可核对消息的「选字」模式出现；工具条可换行，保持原 48px 触区；触摸、键盘和辅助技术共用原生 button。
- 组件与状态、图标与符号、内容与文案：沿用 Solar 引号和可见动词，显示核对中、已引用或待核对；成功回显刚才那段的短摘录，不显示默认全文成功。
- 动效与过渡、导航与架构、反馈与恢复：同一页操作，不建第二套弹层；手动返回走原返回路径，阅读位置、原选区与编辑中的正文互不替代。
- 图像与媒体、手感与性能、数值与监控：不加载图片、不穿透选中操作；只在点击时比对全文，不估算来源权重或编造进度。

**待实机复核。** 草稿先写半句；在有两处相同短语和跨行 / 表情的原消息里特意选第二处，点引用，检查草稿正文、来源和选区。对照超长选区、引用途中更换选区、退出未确认及嵌套表格。此记录不声明已完成 Android、TalkBack 或设备手感验证。
