# 通知中心的待处理事项、更新与原件

在 0.1.140，原工作、协作为何等待、外部消息三者均已能用原对象进入；2026-11-10 的 [既有通知研究与 NC-01–08](./notifications-research-20261110.md) 已明确权限、数据保留、分页、原对象身份和失败边界。不要再建一个通知库或审批中心。本轮是在 c77223a 的三条真实读取路径上换信息结构，原输入不移交给第三方，不新增权限、订阅或工作执行。

## 产品动作与参考
- [Linear Inbox](https://linear.app/docs/inbox) 把优先与一般更新分开，点回原议题。本产品采用判断「需要我做事吗」的入口，不凭主观重要性替第三方消息造审批，不引入 snooze、云端存储。
- [GitHub inbox reasons](https://docs.github.com/en/subscriptions-and-notifications/reference/inbox-filters) 区分被请求 review、被提及、已读/未读等：采用「收到/已读 ≠ 业务完成」，不用 issue 类型和未读状态推断 PocketWorld 工作要授权。两者均只查公开用户路径，非闭源代码。
- [Novu useNotifications](https://github.com/novuhq/novu/blob/338843b8f40ed64d8b8763da6dac55cf8ae9ad5f/packages/js/src/ui/api/hooks/useNotifications.ts) 用实际 filter 对返回事件分流并保留 hasMore；[NotificationList](https://github.com/novuhq/novu/blob/338843b8f40ed64d8b8763da6dac55cf8ae9ad5f/packages/js/src/ui/components/Notification/NotificationList.tsx) 以对象列表、原选择和视图生命周期管理列表，不把后台缓存挂成业务结论。借机制，不引入 Novu 或第三方凭据。PocketWorld 使用原 history.read/teams.attention/remoteInbox；不改原生通知、HTTP、权限或审批。
- 首次进入显示「待我处理」，原工作和协作各用一个入口打开所属对象。需要决定的工作打开原工作及当前处理信息，暂停和中断打开原工作概览。协作沿原运行、成员、分工、问题和代次定位。「更新记录」显示工作结果或外部消息。通知页返回时恢复入口对应的工作区，手机对话沿原会话和草稿校验恢复。
- 从原任务返回仅在观察到同一原生 taskId 曾经打开并退出后重读原游标。事项消失只说「不在当前页」，不说已完成。工作待处理与结果的翻页深度分开记忆，协作保留原定位；远程系统通知按原配置、序号、来源键及原打开修订定位，可定位已归档但不会修改它。接收连接、权限、通道和故障检查在外部消息设置，不再霸占待处理页。一页数字不是全部队列或未读总数。

## 对照 15 个系统：设计基线与待验动作
参考[权威审美库](https://chatgpt.com/space/page_6c522c5579c08191944bb585f4bf5708)与本项目 [DESIGN](../DESIGN.md)。下列均为设计取舍及正式验收条件，不是已测结论。

| 系统 | 落点；实物验收 |
|---|---|
| 配色与表面 | 真实活动标签沿既有 selected/ink，不给普通未读和工作等待一律上警示色；浅、深、高对比均可读。 |
| 形状 | 两个主标签、干净连续工作行，不把每次提醒做成独立控制台；缩小屏宽不产生横滚卡片。 |
| 空间 | 主判断在前，按来源分开呈现真实列表。393px 下列表行给长工作名留出换行空间。 |
| 排版 | 标题 > 对象原名 > 当前动作/实际摘要；长中英、字号放大、空摘要可辨入口。 |
| 组件状态 | 沿 BoardUI Tabs、Button、IconButton、原配置 Dialog；切去更新读对应页，无权限、无资料与空页有区别。 |
| 动效 | 复用已批准的标签选择/减少动态；回位聚焦原对象，不播放虚构完成动画。检查快速反向切换。 |
| 图标 | 复用已有的中性状态、箭头和刷新图标。工作行以文字说明当前状态与所属对象。 |
| 媒体 | 本页不需要图片/媒体；远程正文不因展示而加载图片、自动打开外链。 |
| 导航与架构 | 待我处理 → 原任务/问题 → 原队列，与更新 → 工作结果/外部消息分开；系统通知直达原消息，返回原层。 |
| 跨尺寸输入 | 单列与可换行来源开关；TabPanel/键盘语义来自原组件，返回焦点不强抢正在编辑的人。393px/TalkBack/大屏体验待验。 |
| 材质与层级 | 状态与权限移入现有配置层，列表用轻分隔而非重复大卡；不增加全屏玻璃和遮住末行的工具栏。 |
| 内容与文案 | 「更新记录」「工作结果」「外部消息」说清读的对象。空扫描窗有后续游标，不说全部结束。 |
| 手感/感知性能 | 只打开所选面对应的读取通道，重读真实游标；返回不清筛选，不重新下载所有历史。不能用源码证明帧率。 |
| 数据与监控 | 不画进度图，不将团队成员数、任务页长与远程未读相加；只标注本页项数、真实外部未读、真实连接状态。 |
| 任务反馈/恢复 | 打开或标已读绝不审批；重读后对象缺失只提示不在本页；设备上核对同 id、同草稿、同分工、同归档消息。 |
