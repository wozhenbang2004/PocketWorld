# 长对话：看最新，再回到原处

对话里已能跟随新回复并保存普通阅读进度；它不是临时回程点。人在旧回答中段时，输入区上方的「查看最新」单独记住这次出发的位置。读完点「回到刚才读的位置」，或关闭入口留在这里。切换话题或原生页面身份会清除这份临时位置，它不写入草稿、书签、工作、许可或账号。应用重启不保留。

**来源与取舍。** [Operit 导航器](https://github.com/AAswordman/Operit/blob/7a39941bad80209973c535046a18195c5da9e647/app/src/main/java/com/ai/assistance/operit/ui/features/chat/components/ChatScrollNavigator.kt#L99-L158)区分实际操作与可见消息，不沿用全屏定位轨道。[AionUI 消息目录](https://github.com/iOfficeAI/AionUi/blob/e108b6b56b1a6eb99a00904878d0582f657b2908/packages/desktop/src/renderer/pages/conversation/Messages/MessageList.tsx#L617-L650)按原消息身份查找，不拿相邻项替代。本次只读已经呈现的原对话，不代用户换窗或读取更多历史。[Open WebUI](https://github.com/open-webui/open-webui/blob/0666e59d26a4d056e0bacee41742486badd71cf8/src/lib/components/chat/Chat.svelte#L3523-L3579)区分跟随意图和当前滚动尺寸；保留本项目既有跟随，不用新消息触发回程。

**验收边界。** 基线 `b849a80`，实现位于 `ConversationReadingNav`、`useConversationReading`、`conversation-reading-place`。以下沿[十五系统清单](https://chatgpt.com/space/page_6c522c5579c08191944bb585f4bf5708)及 [PocketWorld 的 PW-UX01–15](../DESIGN.md)给出本次设计落点与复验条件。生产构建只证明编译打包；未在实体 Android、TalkBack 或真实长对话上验证效果。

| 系统 | 设计落点与需观察的结果 |
| --- | --- |
| 配色与表面 | 沿用原返回胶囊的纸面、墨色、次要字令牌；浅深色都能识别动作，无新增警示色。 |
| 形状与圆角 | 两个相关动作共用单一轮廓，不给每个消息套容器；检查反馈换行时边缘是否完整。 |
| 空间与密度 | 沿输入框上沿的原位置，只在离开末尾、有新回复或留有回程时出现；短对话不多一行。 |
| 排版与可读性 | 短动词优先，详情只在回程受限时出现；窄屏与大字号下长提示能换行。 |
| 组件与状态 | 采用项目现有 BoardUI Button / IconButton（Figma `3656:13819` / `3731:3035`）；最新、回程、收起语义不同，均不发送输入。 |
| 动效与过渡 | 沿原 `pw-new-replies` 入场，定位直接完成；开启减少动态仍可一去一回，不用长平滑滚动追逐流。 |
| 图标与符号 | 原 Solar 向下、折返、关闭；方向按钮带可见动词，关闭键带可读名称。 |
| 图像与媒体 | 无新增装饰图或外部加载；图文重排后优先用原文字锚点，不把旧屏幕百分比当原位置。 |
| 导航与架构 | 当前话题内的临时往返；切换话题、原生文档重绑后不出现另一话题的回程点。 |
| 跨尺寸与输入 | 指针和键盘共用真实按钮，44px 最小触区。返回把焦点给消息，关闭留在当前阅读区，不聚焦输入框。 |
| 阴影与材质 | 只沿用原浮层的轻阴影与安全区，正文不加玻璃；检查首行和末尾是否可读。 |
| 内容与文案 | 出发点在未保存草稿等区域、无法标记时先停住，明确选择「只查看最新」后才单程跳转。返回时历史窗口缺消息则不滚动；文字已变化时说明只定位到了原消息。 |
| 手感与性能 | 滚动仅增加常量距离判断。字形范围、原消息查找只在显式往返时计算；没有实测帧率或耗时。 |
| 数值与监控 | 不适用：不新增未读计数、历史覆盖率或百分比，不把呈现的消息数当完整历史。 |
| 反馈与恢复 | 尝试连续操作、流式更新、字体改变、空加载、原文消失、切换话题；只在原窗口和消息身份匹配时返回。 |

**实机路径。** 打开一份已有的长对话，上翻到长回答中间记下一句，点「查看最新」，在新回复出现后点「回到刚才读的位置」。比较同一行与窗口上缘的相对位置；再核对仅关闭入口、字体改变及切换话题时没有误跳、误发送或弹出审批。

### 原回复 → 文档读取回执 → 原回复

普通已保存回复的「消息操作与来源 → 这条回复的执行轨迹」与原回复的进展入口共用原生任务、执行轮次及 epoch。原执行已换轮或不能核对时停在原话题，不把新一轮的内容当作旧答案的依据；只有工作编号的旧消息明确标成当前进展。轨迹只有一笔已结束的文档读取时，可直接打开该笔；多笔可筛选后按轮次与记录号挑选。这里只证明工具当时返回了什么，不证明模型在答案中用了这些片段。

沿现有 BoardUI 控件、Whaleness 轨迹行和 Vaul 阅读层。原请求的附件编号和摘要与回执一致才展示正文，空范围、格式不支持、加密、解析失败与来源失效各说各的。未核对的结果不回退成原始 JSON；查看不补读附件。原来源状态变化或退到后台后，不自动重新取得片段。关闭片段回到原入口，从执行过程退出回到发起它的消息和阅读位置。

待实际体验：在同一长对话找一条有两次文档分段读取的旧回复，分别对照页码和文字，连续返回两层；再观察原件撤回、同名不同版本、普通解析失败、工作换轮及后台恢复。源码与编译不代替这些观察。
