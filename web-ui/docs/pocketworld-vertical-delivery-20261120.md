# PocketWorld：先做成一件事，再扩成设备生态

产品承诺：在原对话里说清想做什么；管家准备合适的工作，让主人只在真正的分界上确认；回来能够打开、检查并接着用同一份结果。聊天回答、拟好的计划、已接单和验收完成不是一个状态。

## 第一条纵向交付：一个本机项目、一个独立改稿

验收语句：「在我明确选的本机项目里改这一处。别覆盖原件，先把改稿和差异带回来。」

1. 既有普通对话原生保存准备提案；回复旁出现“核对项目工作”，没保存不得伪造卡片。“尚未开始”必须明确。
2. 只问还缺的东西。项目/副本已经确定时尊重原生证明，不用模型文字当作确认。原工作审阅明确“只出改稿和差异”，不写仓库、不改原副本、不运行命令。
3. 原生结果必须是一份实际独立稿和可核对的新旧差异，带原任务/轮次、原副本及原文件版本。没有真正的产物，就显示原因，不把报告当产物。
4. 回原对话能打开原结果；下一次“继续”只能沿主人明确选择的原件。不默认切换到最近任务或最新轮。写回、执行或另一个设备必须独立确认。

这是首版唯一发布目标；选一个独立作者先完成实物。独立审阅作为同一稿的下一道可选检查。不借现有团队批准自动触发完整项目的整合。原整合在第一笔文件确认后结束原执行，不能把新增启动按钮当闭环。

## 第二条：一句话委托手机做一件可核对的事

验收场景：主人明确要求使用本机已装计算器核算一组输入。普通计算可以直接回答，不默认开 App。明确要求设备时走原准备和范围确认；返回原对话显示实际看见的 App 与结果。切回或关闭 App 后，只有原轮真正保存的状态才可说已开始、仍运行或已交付；断开/权限缺失给一项有效的下一步，不擅自重跑。

## 协同扩展的先后

- 跨安卓：同一委托只在主人主动选另一台已配对、已有当前资格的手机时显示。原授权及对端原核对须保留，目标不在线不得静默回落本机，也不能用旧权限猜资格。
- Windows／自带 Linux：同一产品意图及结果返回规则，不混报能力。Windows 伴侣现有定向文件工具不等于电脑已能接受整个目标；正式安装、明确的受限项目交办和双机验收都是前置，不以手机上的模型或 SSH 代称 Windows Agent。自带云也不暗中同步。
- 记忆：用于同一委托已经批准的原约束、已交成果和用户明确引用的材料。不增加全局最近/个人档案读，不推测“上次”。
- 不再并行堆状态页、历史筛选和打包工具；除阻断本纵向旅程、已经验证的回归或防止真实损失外，挪回待办。

## 验收线

用专门的中性文件项目手工走完两次：正常交付及原件在审阅期间变更。记录从聊天到可查看差异的步骤、原件前后 SHA、没有命令或写回的原回执、重开应用后从原会话找回同一稿。再分别记录一个拒绝/无能力分支是否留下原始意图。不能执行真机时，区分源码接通、编译出包和当事人体验，不把 CI 替代手验。不访问用户电脑。

## 从交付走到复用，而不是再建一个工作区

- 原回复随实际工作变化：未开始时核对这次意图；执行中查看这次工作；有真实改稿时点一次就看原差异。只读取这一轮、这一份草稿，不能因为原执行轮次或版本变化偷偷展示另一份，也不能把正文混入概览。
- 成果里区分两件事：「我自己改并另存」和「把我明确选中的已保存版本交给管家继续」。如果看的是最初版本，不能自动切到我的最新版本。第二次交办是新任务，有自己的原对话、目标、确认和差异。未证明原来那份继续可用时，不回退工程原件启动。
- 可脱离 App 使用的第一步是显式保存单份改稿文件（只保存所看的精确版本，不附完整原件、不分享、不覆盖）。下载去向默认是「下载/PocketWorld」；系统另分配同名文件，回读核对后才说已保存。这个副本离开 App 私有空间，不由 PocketWorld 自动发给别人。应用到工程原件排后，保留独立确认和可核对的并发安全。
- 下一条手机任务须先证明有严格的本次 App 范围和真实观察，不能拿「模型答案正确」验收手机确实动过。下一条 Windows 任务同样先做最小的实际改稿，源仍留在已配对且具备这项能力的设备上；不把现有文件读取或可请求连接冒充接受目标。

本轮外观复核以审美库「格式塔与最小必要表达 / 渐进披露」为准：行动跟原回复同组，已完成后的主行动应取代旧入口而不是再加一排；文件名、同屏差异和下一步是主层，运行记录、版本指纹和路径留在次层。取消、没有产物、所选版本不可读属于关键反馈，不藏在详细日志里。回原对话保持阅读位置。颜色、布局、动效手感、键盘及 TalkBack 验收仍需实际设备，不以源码样式替代。

### 再交办：从实际点选的某一稿继续

在原私聊里说新的要求，从项目提案中选择「接着改我另存的一稿」。先显示具体版本和新目标；只有明确选择并确认发送给这一轮实际使用的模型后，项目作者才读取该单一文件，不从原工程、其他会话、更新的稿或未保存输入补位。撤回原来源、换模型或关联不明就停止，不准换接收方。返回的新差异左侧是当时点选的已存稿，右侧是新结果；不覆盖原工程及来处稿的任何版本。

实际手验先保留同路径的两个版本，选早的一个，检验第二次交付的左边正文与 SHA、原件和较新版本前后都不变。断网等无真正新草稿则不报成功。

## 从检查差异到独立可工作的工程

- 从原委托已打开的实际改稿或明确保留稿建副本。原稿来源经过多次接续时，要沿真实任务记录找到最初 checkout 的整树源码摘要；新任务单篇稿的摘要不能充当工程底本。最初纳入的文件路径或字节变过就停，不把旧稿套到现在的文件。空目录和可执行位在这次建副本审阅时另行固定，不冒称最初改稿时也曾保留这些信息。
- 第一次只在本机另建工程与工作副本，复制原生源码包允许的字节、二进制、空目录与可执行位，仅一条既有路径换成所选稿。审阅显示文件数、被排除项数和目标；临时目录中的实际文件通过回读后才发布。私有配置、依赖缓存、Git 历史和权限不迁移；没有构建、运行、签名或上传。
- 重开原对话的同一改稿，只按固定版本查这一个副本。打开后走现有项目工作台，可返回原任务。尚未打开使用的副本可明确收起再还原，两个动作都是移动原目录，不删除、覆盖或再复制。开始用过的副本不再从原稿快捷回收，以保护后续工作。
- 离线中性样例手工观察了源项目三件文件（含二进制与脚本位）、空目录、A1 非最新稿来源、B 独立改稿、新项目正式登记及独立目录读回、未使用副本移回/复原、原树变更拒绝。未运行示例脚本，未在设备上交办或构建。
- 若建立时进程停在“项目已登记、实际目录未发布”之间，这个项目不会显示成空白工程。原稿只显示「继续核对这份副本」，重新确认也只补全同一次建立。查看目录登记不等于使用副本，不影响尚未打开时的收起。

## 周末：回到原工作后能接着做

常用旅程先按「原入口 → 当前对象 → 已保存结果 → 返回原位」收口，不新增状态页。全局搜索里区分结果列表没读完和某条原记录没打开：前者重读搜索，后者可重试同一条。原工作页面接收打开失败时，回到原查询、筛选和已读位置，不让空任务页遮住选择，也不新开任务或重派。沿用现有 BeUI/Affect 搜索布局、选中行及反馈方式。可观察验收：从至少两页的搜索结果打开一条工作，不能读取时原结果仍能定位，重试不会翻到下一页；成功后返回同一查询。打开对话或项目须看到宿主窗口已选中对应对象；原输入忙时，只读窗命中同一对话也可算打开。在确认前不把旧页面标作搜索命中的记录。生产 Android 界面、手势及完整回程尚待真实体验。
