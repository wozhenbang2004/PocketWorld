# PocketWorld：先做成一件事，再扩成设备生态

产品承诺：在原对话里说清想做什么；管家准备合适的工作，让主人只在真正的分界上确认；回来能够打开、检查并接着用同一份结果。聊天回答、拟好的计划、已接单和验收完成不是一个状态。

## 第一条纵向交付：一个本机项目、一个独立改稿

验收语句：「在我明确选的本机项目里改这一处。别覆盖原件，先把改稿和差异带回来。」

1. 既有普通对话原生保存准备提案；回复旁出现“核对项目工作”，没保存不得伪造卡片。“尚未开始”必须明确。
2. 只问还缺的东西。项目/副本已经确定时尊重原生证明，不用模型文字当作确认。原工作审阅明确“只出改稿和差异”，不写仓库、不改原副本、不运行命令。
3. 原生结果必须是一份实际独立稿和可核对的新旧差异，带原任务/轮次、原副本及原文件版本。没有真正的产物，就显示原因，不把报告当产物。
4. 回原对话能打开原结果；下一次“继续”只能沿主人明确选择的原件。不默认切换到最近任务或最新轮。写回、执行或另一个设备必须独立确认。

这是首版唯一发布目标；选一个独立作者先完成实物。独立审阅作为同一稿的下一道可选检查。不借现有团队批准自动触发完整项目的整合。原整合在第一笔文件确认后结束原执行，不能把新增启动按钮当闭环。

## 第二条：一句话委托手机做一件可核对的事

验收场景：主人明确要求使用本机已装计算器核算一组输入。普通计算可以直接回答，不默认开 App。明确要求设备时走原准备和范围确认；返回原对话显示实际看见的 App 与结果。切回或关闭 App 后，只有原轮真正保存的状态才可说已开始、仍运行或已交付；断开/权限缺失给一项有效的下一步，不擅自重跑。

## 协同扩展的先后

- 跨安卓：同一委托只在主人主动选另一台已配对、已有当前资格的手机时显示。原授权及对端原核对须保留，目标不在线不得静默回落本机，也不能用旧权限猜资格。
- Windows／自带 Linux：同一产品意图及结果返回规则，不混报能力。Windows 伴侣现有定向文件工具不等于电脑已能接受整个目标；正式安装、明确的受限项目交办和双机验收都是前置，不以手机上的模型或 SSH 代称 Windows Agent。自带云也不暗中同步。
- 记忆：用于同一委托已经批准的原约束、已交成果和用户明确引用的材料。不增加全局最近/个人档案读，不推测“上次”。
- 不再并行堆状态页、历史筛选和打包工具；除阻断本纵向旅程、已经验证的回归或防止真实损失外，挪回待办。

## 验收线

用专门的中性文件项目手工走完两次：正常交付及原件在审阅期间变更。记录从聊天到可查看差异的步骤、原件前后 SHA、没有命令或写回的原回执、重开应用后从原会话找回同一稿。再分别记录一个拒绝/无能力分支是否留下原始意图。不能执行真机时，区分源码接通、编译出包和当事人体验，不把 CI 替代手验。不访问用户电脑。
