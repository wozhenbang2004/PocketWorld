- 对话是主入口；任务用于核对实际执行和介入；项目承载原文件与预览。记忆、自动化、团队、技能工具、设备与媒体属于直接可达的工作区；设置仅承载配置与偏好。

## 字体

设置路径：设置 → 手机能力 → 外观与字体。中文6种、英数12种、代码2种（代码2种属于英数12种），共18家族。默认 Noto Sans SC / Inter / JetBrains Mono。选择只预览，显式保存后由同一 native appearance snapshot 应用于主界面、内置浏览器、阅读器和启动界面。

三个角色以一次严格校验的 settings.typography 命令原子保存到现有 ui_presentation 偏好。未知值不能进入CSS，旧宿主不支持时明确禁用。磁盘写入返回失败或回执不完整时保留选择并允许重试；accepted不能冒充保存成功。恢复默认组合也需显式保存。

完整字库固定官方来源/commit/blob/size/SHA256及OFL，见 scripts/font-sources.json；共21字体文件，92,862,520字节原始数据。生成缓存及打包资产不提交Git，可按脚本重建。字体按使用加载，不一次请求18家族。全套字库增加安装包体积；不以样张子集冒充完整字体。

## 动效与状态

采用 Motion、现有 BoardUI/React Aria、BeUI 和 Vaul。只对表面和连续布局做表现动画，权威任务、编辑器和媒体节点不被过场克隆。reduced-motion 下取消多余跟随、回弹与位移。动画中可中断、返回；禁用与pending必须同时锁定视觉输入和真实值。

执行圆环/细线只显示原执行信号；未知、部分记录、效果待确认保持明确。不添加演示计时、伪造百分比或样例任务。移动触控目标至少44px；深色需保持层级和文字对比。

## 2026-11-08 Android / iOS 交互与页面重构

用户本轮要求“研究安卓苹果软件的 uiux 设计然后去大范围深度重做我们 pocketworld 的 uiux”。从 main `cfc74c8ebeb20a984cbc285d26e60414cae179c8` 出发；以下是本轮采用的实现基线，尚非用户逐屏审美认可。实际目标仍是 Android 上同一 React / WebView 业务前端，iOS 作为交互研究来源。

### 统一页面语法

- 手机继续抽屉导航，主入口是对话、任务、项目；近期对话属于对象列表，更多工具和设置是低频入口。宽屏沿用同一工作区和可收放侧栏，不能重挂载草稿或编辑器。
- 对话以阅读和输入为中心：标题与模型分层、正文可连续阅读、执行中的事情归到同一工作区、补充和停止仍绑定原任务。输入框随真实内容增长，附件与工具按需披露，禁止示例内容静默变成用户草稿。
- 集合页使用“主对象工具栏 → 搜索/本地筛选 → 有意义的对象分组 → 对象行”。首屏不出现第二份大标题或说明文章；待处理事项优先于运行记录，运行记录优先于历史。
- 对象详情使用“状态和主操作 → 主要内容 → 相关对象 → 可展开的技术/历史信息”。结果、权限、费用、错误、未决状态保持可见，不能为了简洁折叠必要决策依据。
- 设置首页是少量常用入口加分组导航行；进入分组后才显示具体设置。行首是稳定图标锚点，中间是名称及真实当前值，尾部为状态或进入箭头。长编辑走现有完整子页面；短选择与临时核对使用单层浮面。
- 编辑页沿用现有字段、显式保存和草稿返回；正文只保留一个主要纵向滚动区，保存/取消在窄屏和短屏可达。读取、接受、执行完成三种状态不得混写。

### 视觉与触控规则

沿用 Paper / Graphite 唯一颜色源和既有三角色字体，不引入新皮肤或依赖。页面标题 18–20px / 600，重要对象 15–16px / 600，正文及输入 16px，元信息 12–13px。手机边距 16–20px、组内 8–12px、组间 24px 起；可点击对象行至少 56px，独立图标与主要触控目标以 48px 为基线。图标本身可为 18–22px。长中文、320px 窄屏、深色和大字号必须保持阅读顺序，不把单行省略用于唯一的关键决策内容。

页面和列表保持平面，组内以邻近和轻分隔组织；输入、选择对象和临时浮面可有弱表面。圆角和内边距共同保证文字安全，不用全页重复大卡片承载每一个字段。内容区使用实色；材料/透明效果只用于必要的控制层，不给长文阅读铺玻璃。

继续使用 BoardUI / React Aria、Affect、BeUI、Motion、Vaul 的现有适配。按压约 120–160ms、披露 180–240ms、抽屉 240–320ms 为本轮调参起点，非平台强制规范。动效呈现真实选中、展开和空间归属；允许中断，减少动态时取消非必要位移。返回依次处理当前浮层、对象详情/编辑、上一页面；保持已有草稿、查询、滚动和权威身份。

### 具体问题与修正要求

- 首页将模型缩成标题下的小字，推理只能沿多层模型核对表单找到；大块留白与不完整的输入操作面同时出现。改为双层 composer：上层输入，下层附件、明确模型名称、实际推理状态和发送。语音与发送按草稿状态共用主要操作位；320px 或大字体允许控制组换行。模型与推理使用真实宿主回执，不本地伪造高／中／低状态。

- 会话标题只表达当前会话；模型控制归输入现场。空白首页只提供实际能力入口，不生成示例任务、虚假进度或静默写入草稿。消息阅读区、正在办理的真实任务与输入区有不同权重。

用户提供 v0.1.19 实机展开图后明确纠正：“点击模型就出来模型的 点击推理就出来推理的，你他妈现在点击任意一个出来的是两个都有的”。这一要求替代此前 PW-UX-C2 合并模型/推理面板的设计决定。截图还直接暴露权限 Popover 过高、内容延伸到输入工具栏，以及单模型和单项推理被重复大块分段控件挤占的问题。原聊天主界面的图证与行为测试没有充分覆盖这些展开状态，不作为本反馈已解决的证据。

### 当前交互与构图要求

- **模型入口只选择模型。** 标题“选择模型”，进入后直接看到模型目录；不再显示“模型 / 推理”切换，不在会话模型详情中编辑推理。搜索、收藏/最近使用和来源保持可达，但不叠两排大型分段表面。模型行显示名称、来源和真实选中状态，详情独立可点。“恢复使用默认模型”属于此入口，保持原生清除整份会话覆盖的真实语义。
- **推理入口只设置当前模型的推理。** 标题“推理强度”，仅显示原生声明的可用选项；选择“服务默认”不改变模型身份或输出/图片预留。若只有服务默认，以简短的当前状态说明呈现，不铺一张大表单，也不编造高/中/低。模型列表、管理 AI 接入和恢复默认模型不进入该面板。
- **执行权限是独立、有限高度的 Vaul 面板。** 应用范围同一行；三种审批方式采用紧凑可点行与短说明；工具规则默认折叠；保存有明确回执。内容随实际需要增长，短屏只滚动面板正文，不从聊天工具栏向上撑出一张无边界 Popover。当前任务范围渐进披露；实际待处理事项保留直接入口。状态用用户文案，不直接露出 `needs_confirmation` 等内部值，也不把结果核对叫作工具授权。
- **关闭与保存保持一致。** 点击关闭、遮罩、拖动和原生返回都服从同一写入 pending 状态；模型、推理、权限保存未定时不得关闭后重派。退出回到相应入口，草稿和聊天滚动位置保持。权限层出现时，原生项目预览和手机查看层遵守现有遮挡协议。
- **只调整这三个控制入口。** 沿用 BoardUI / React Aria、Vaul、原字体和 Paper / Graphite；保持双层输入框、语音/发送/停止关系和原生任务权威。权限策略不扩大任务范围，模型/推理修改不重建已启动任务。
